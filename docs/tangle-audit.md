# Tangle audit and deferred recommendations

Audit date: 2026-10-22. Status: retained for future development; no mesher
change is implemented or scheduled by this document.

Baseline: luafemm 0.9.0-dev, commit
`93620f0d04569877491a0c1079ea27bd32ab79f4`.
Tangle: version 0.4.18, commit
`66221c398cd90f06a7beb0c0abf637b269313af3` in `../tangle`.
See also the [broader capability roadmap](femm-capability-roadmap.md).

## Recommendation

Selectively adapt Tangle's algorithms into the existing Lua mesher. Preserve
the pure-Lua runtime, generic TeX interface, arbitrary supported TikZ paths,
exact geometric predicates and independent mesh audits. A wholesale translation
would duplicate existing functionality and import different failure policies.
The C++ executable can be an optional development oracle, never an installation
or compilation dependency for users. Native timing does not predict Lua timing.

## Source findings

Locations below refer to the pinned Tangle revision, not to a moving branch.

| Source | Finding and implication |
| --- | --- |
| `tangle.cpp:1825`, `:2063` | Refinement uses local updates and a spatial grid for encroachment queries. Our local updates already exist; indexing the current global segment scan is a concrete improvement. |
| `tangle.cpp:2435`, `:2570` | Short-edge-priority refinement can insert off-centers instead of circumcenters. Evaluate element count and accuracy together. |
| `tangle.cpp:2190`, `:2410` | Corner-aware split positions and acute-apex ancestry limit refinement cascades. Port with an explicit quality-exception policy. |
| `tangle.cpp:1762`, `:2260` | Vertex/segment size data influence area targets and survive segment splitting. This is useful for local density control, not proof of an arbitrary smooth grading guarantee. |
| `tangle.cpp:2330`, `:2706` | Periodic chains have paired nodes and synchronized splits. The solver must separately enforce periodic/antiperiodic degrees of freedom. |
| `tangle.cpp:3343`, `tangle_mesh.h` | FEM input, protected air-gap boundaries and air-gap metadata support machine workflows. Specialized air-gap coupling is a separate solver project. |
| `tangle.cpp:267` | Filtered predicates fall back to finite `float256` precision. The comments explicitly distinguish this from unconditional exact expansion arithmetic. Retain our predicates under their documented exponent assumptions. |
| `tangle.cpp:2490`, `:2536`, `:2665` | Retry caps, corner exceptions and failed-insertion guards can leave triangles below the requested quality. The refinement budget also bounds the loop; it does not certify the target. |
| `tangle.cpp:4790` | Unrecoverable constraints cause an explicit mesh error rather than an invalid output mesh. |

The existing Lua code already provides constrained Delaunay triangulation,
local Lawson flips, short-edge priority, exact orientation/incircle/diametral
tests, holes and domain carving. Its missing acute-corner protection and its
global segment scan are documented in [meshing.md](meshing.md). Tangle's optional
reverse Cuthill-McKee ordering is another experiment: luafemm currently sorts
nodes geometrically before IC(0), so any benefit must be measured on solver
iterations and total time, not merely bandwidth.

The inspected xfemm CMake file offers both Triangle and Tangle, defaults to
Triangle, and pins Tangle to `a808c624ec0584569e43593662f54890b602c6af`.
That pin differs from the audited sibling clone. Any future comparative runner
must record the actual backend and revision instead of assuming they match.

## Native smoke tests

Tangle compiled successfully on the macOS development host with:

```sh
mkdir -p build/tangle-audit
c++ -O3 -std=c++17 -o build/tangle-audit/tangle \
  ../tangle/tangle.cpp ../tangle/float256.cpp -lm
```

Inputs were existing luafemm exports generated by the interoperability suite,
copied from `build/interop/` into `build/tangle-audit/`. Never run the CLI on
upstream fixtures in place: it writes output beside the input.

Original input SHA-256 values:

| Input | SHA-256 |
| --- | --- |
| `coil-3.fem` | `b932f198c54bda8227b5864384f7084cb2af506fcbc4fa7fce9d6e879535d69a` |
| `machine-coil.fem` | `1e5cc067b26c7c2f16a521ebde9098ba96eb752e3ff289d04cc28d116f786c38` |
| `machine-sine.fem` | `f3a695078538a939de22e343c17ad7c9f9758176f860564569087dffc0501416` |

All three original files failed with exit code 4 and "Input: 0 vertices".
The reader checks `<EndBdry>` and `<endbdry>`, but luafemm emits `<Endbdry>`;
the same issue affects `<Endblock>`. It consumes the remaining input while
looking for a recognized closing tag. xfemm accepts these exports. Lowercasing
the angle-bracket tags in disposable copies resolves this failure. This is a
reader compatibility issue, not evidence of a triangulation failure.

For each normalized copy, `[minangle]` was set to 1 or 25 in the file and the
CLI was invoked with that `.fem` filename. Setting `-q25` alone is insufficient:
the FEM reader overwrites the quality option from the file. Other input data
were retained. Output `.node` and `.ele` files were independently read in Python;
signed areas and every triangle's minimum angle were recomputed.

| Input | Target angle | Vertices | Triangles | Measured minimum angle |
| --- | ---: | ---: | ---: | ---: |
| U electromagnet | 1 | 24 | 42 | 1.682329 |
| U electromagnet | 25 | 166 | 307 | 25.325901 |
| Machine coil | 1 | 2340 | 4670 | 1.017804 |
| Machine coil | 25 | 4304 | 8555 | 25.017049 |

All normalized runs exited successfully. None contained a nonpositive signed
triangle area or an angle below its target by more than 1e-8 degrees.
These are smoke tests, not a complete constraint/material/coverage audit,
not a field-solver comparison and not a benchmark against the Lua mesher.
Raw disposable inputs, logs and JSON results remain under `build/tangle-audit/`;
this table and the input hashes retain the evidence if build products are removed.

## Deferred work sequence

1. Establish a pinned comparative corpus: tilted and curved U cores, permanent
   magnets, narrow gaps, many slots, acute corners, nested regions, holes and
   intersecting paths. Measure runtime, memory, topology, quality and field
   convergence. Check translated, scaled and reordered versions of geometries.
2. Index segment searches, then add optional off-center insertion as separate
   changes. Preserve deterministic ordering and exact final predicates. Profile
   the Lua implementation before considering Tangle's approximate bucket queue.
3. Protect acute corners. Keep strict mode; explicitly identify any unavoidable
   geometric angle exceptions and report achieved quality separately. Never
   silently convert insertion failure or budget exhaustion into success.
4. Extend local size controls on points, boundaries and regions. Preserve
   assignments through splits and expose them through PGF keys/styles. Document
   geometric curve tolerance independently of element size and size grading.
5. Implement paired periodic boundaries and specialized annular air-gap coupling
   only together with the corresponding solver, cache and interchange changes.

At each stage validate material interfaces, boundary tags, ideal-model flux
constraints, cache invalidation and all three TeX formats. Keep existing paths
and readers; there is no need to port the C++ ABI or `float256` library.
